## 问题 1：`IMnvPODDataBaseDetection::Compute` 的 `std::string&` 出参导致 Python 无法调用

**现象**：基于定轨数据的机动检测 `Compute` 的参数 `strDetectDVutc` 在 SWIG 封装中为 `std::string&`（出参）。Python 侧传入 `str` / `bytes` / `bytearray` / `None` 均抛 `TypeError: argument 3 of type 'std::string &'`。

**已尝试的 SDK 侧规避（均不可行，属接口封装层无法解决的问题）**：
1. 逐类型实测实参：`""`、`None`、`b""`、`bytearray()`、`str` 子类——全部被拒；
2. 模块内无字符串指针助手：仅有 `new_int_p` / `new_double_p` / 三个枚举指针助手，无 `new_string_p` / `new_char_p`；`dir()` 全量扫描确认无其他 string 相关工厂；
3. 生成的 `ATKComponentPythonModule.py` 中无任何 `SWIGTYPE_p_std__string` 代理类，无法构造/复用 `std::string` 指针对象；
4. 模块无脚本执行桥（无 `ExecuteScript` 类接口），无法绕过 SWIG 直接调 C++；
5. Connect 命令库无机动分析命令，无替代调用路径；官方示例中也无 POD 检测的调用范例。

**影响**：`IMnvPODDataBaseDetection.Compute` 在 Python 二次开发中完全不可调用（机动分析的 POD 变体不可用；TLE 变体 `IMnvTLEDataBaseDetection.Compute` 出参为 vector，正常）。

**复现步骤**：
1. 在 ATK 安装目录下运行 `Python/_internal/python.exe Z:\<路径>\repro1_pod_compute.py`（wine）；
2. 脚本依次用四种类型作为 `strDetectDVutc` 调用 `Compute`，全部 `TypeError`；末尾附 TLE 变体的正常调用作对照。

**期望**：为 `strDetectDVutc` 提供 Python 可传的出参形态（如 `std::string*` + `new_string_p()` 助手，或改为与其他出参一致的 `std::vector<std::string>&`）。

## 问题 2：Exec_Report 族命令 ACK 但不返回数据

**现象**：`Exec_Report_RM` 对已配置轨道的卫星返回空字符串；`Exec_ReportCreate` 携带 `File` 选项 ACK 但不生成文件（相对 ATK 工作目录与绝对路径均未生成）。命令本身被接受（不报 NACK）。

**影响**：二次开发无法通过 Exec_Report 族获取报告数据/文件。同类 `QuickReport_RM GetReport` 返回正常（可返回完整报告文本），可作对照。

**复现步骤**：
1. 启动 ATK 并等待就绪（启动加载完成、命令发送间隔充分）；
2. 运行 `python3 repro2_exec_report.py <ATK安装目录>`；
3. 观察输出：`Exec_Report_RM` 返回 `''`，`Exec_ReportCreate` 后文件不存在，而 `QuickReport_RM GetReport` 返回完整报告文本。
